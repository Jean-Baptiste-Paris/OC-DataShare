Contexte

DataShare est une jeune entreprise qui lance un MVP de plateforme de transfert de fichiers sécurisée pour freelances et petites entreprises.

  • Commanditaire : Lisa, responsable produit
  • Mission : référent technique senior
  • Contrainte : démontrer des principes d'architecture (SOLID, séparation des responsabilités, patterns), pas la maîtrise d'un framework

Sécurité

  • Argon2id (OWASP A02, NIST SP 800-63B)

  • POST /login · 401 unifié
  • DELETE /files/{id} · 404 unifié (4 cas)

Démonstration

Parcours bout-en-bout (live) :

  1. Création de compte → connexion → arrivée sur l'espace upload
  2. Upload d'un fichier · obtention du lien public unique
  3. Ouverture du lien dans un onglet privé (destinataire anonyme)
  4. Téléchargement (déclenché par Content-Disposition serveur)
  5. Retour sur « Mon espace » · visualisation de l'historique · suppression
  6. Refresh : le fichier passe en « Expiré » (soft delete)

Bascule mobile via DevTools : drawer + kebab menu sur file rows.

Utilisation de l'IA — posture

Binômage exigeant et asymétrique tout au long du projet :

  • Le référent tech (moi) pilote, conçoit l'architecture, assigne les tâches, revoit systématiquement
  • Le copilote IA propose, argumente, code après validation, montre les diffs

Règle absolue (séance 1) : jamais de code sans feu vert explicite + explication amont (quoi/à quoi ça sert/pourquoi).

Évolution : pédagogie granulaire (étapes 1-2) → supervision rapprochée (étape 3) → vitrine OC sur US01 → collaboration normale (US02-06) → exécution séquentielle qualité (étape 5).

Difficultés rencontrées

  • Divergences silencieuses du copilote par rapport aux ADRs (séance 11 — entité File, StorageInterface). Le copilote a produit du code qui ne respectait pas les décisions actées.
  • Récidive « style customisé vs DS » sur 2 séances consécutives (12, 13). Pattern appris en mémoire après le 2ème incident.
  • Incohérence contrat-interface §4.6 (hard delete) vs modèle de domaine (soft delete via deletedAt) découverte tardivement en séance 13.
  • Wipe BDD entre Cypress et passe UI (confusion datashare/datashare_test).
  • Itérations UI longues (~12-15 micro-ajustements par passe), pas de mécanisme de batching efficace.
  • Surcharge cognitive en fin de séance dense (séance 11 — 5 décisions empilées).

Solutions apportées

  • Mémoire IA persistante — 17 mémoires accumulées (profil user, style de communication, règles de revue, pièges archi). La calibration ne se perd pas entre séances.
  • Règle « grep ADR/conception avant tout code » ajoutée en mémoire après la séance 11. Plus de divergences silencieuses ensuite.
  • Mémoire dédiée style DS (feedback_align_ds_avant_style.md) après le 2ème incident.
  • Workflow seed idempotent (make seed-demo) pour restaurer rapidement la BDD post-Cypress.
  • Découpage en lots sur l'étape 5 — 5 lots séquentiels pour ne pas se perdre dans le scope qualité dense.
  • Recalibration cognitive explicite séance 11 → 2 mémoires ajoutées (profil pro, communication 1 question à la fois).
